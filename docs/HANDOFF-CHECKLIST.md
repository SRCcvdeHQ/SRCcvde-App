# SRCcvde Client Handoff Checklist

Use this checklist for every completed client engagement. The SRCcvde app stores the same lifecycle with timestamps so the operational record and this human checklist stay aligned.

## Before the handoff meeting

- [ ] Confirm the project is ready for handoff and known punch-list items are documented.
- [ ] Schedule the Zoom handoff meeting.
- [ ] Add the Zoom link and meeting time to the client handoff workspace.
- [ ] Confirm the client's primary transfer email address.
- [ ] Prepare the Handoff & Aftercare Agreement for client signature.
- [ ] Prepare the Data Retention Agreement for client signature.
- [ ] Inventory every account to transfer: GitHub, Supabase, hosting/deployment, domain/DNS, analytics, email/API services, and any other third-party account.
- [ ] Confirm all fully executed project documents are present in the SRCcvde document vault.

## During the handoff meeting

- [ ] Walk through the completed site/app and final deliverables.
- [ ] Review repositories, database/backend, hosting, deployment, domain/DNS, integrations, recurring services, and billing ownership.
- [ ] Review administrator and recovery access without exchanging passwords in insecure channels.
- [ ] Explain the included 30-calendar-day aftercare scope and exclusions.
- [ ] Explain that SRCcvde admin access remains only for the aftercare period.
- [ ] Explain the additional 30-calendar-day data-retention window after aftercare ends.
- [ ] Confirm the client is responsible for keeping its own copies before the retention deadline.
- [ ] Document open questions, decisions, and any agreed punch-list items.

## Agreements and ownership transfer

- [ ] Handoff & Aftercare Agreement is fully executed.
- [ ] Data Retention Agreement is fully executed.
- [ ] Client transfer email is verified.
- [ ] GitHub ownership/access is transferred and the client confirms administrator access.
- [ ] Supabase ownership/access is transferred and the client confirms administrator access.
- [ ] Hosting/deployment ownership or billing is transferred, if applicable.
- [ ] Domain/DNS ownership or access is transferred, if applicable.
- [ ] Remaining third-party services are transferred, if applicable.
- [ ] Confirm the client controls MFA, recovery methods, and billing for transferred services.
- [ ] Generate the SRCcvde contract archive ZIP.
- [ ] Deliver the ZIP to the client and ask them to save it somewhere they control.

## Day 0 — start aftercare

- [ ] Confirm all required transfer items above are complete.
- [ ] Start the 30-calendar-day aftercare period in SRCcvde.
- [ ] Verify SRCcvde shows the aftercare end date and the final retention/deletion date.
- [ ] Keep only the minimum SRCcvde admin access needed to provide aftercare.

## During the 30-day aftercare period

- [ ] Handle reproducible defects and reasonable handoff assistance included in aftercare.
- [ ] Quote new features, redesigns, new content, or other out-of-scope work separately.
- [ ] Keep material support decisions and changes documented.
- [ ] Remind the client to download any project data or executed documents they want to retain.

## Day 30 — operational handoff closes

- [ ] Text the client that SRCcvde administrative access is being removed.
- [ ] Log that final notice in the handoff record.
- [ ] Remove SRCcvde from GitHub.
- [ ] Remove SRCcvde from Supabase.
- [ ] Remove SRCcvde from hosting/deployment.
- [ ] Remove SRCcvde from domain/DNS.
- [ ] Remove SRCcvde from any remaining client-owned services.
- [ ] Verify no SRCcvde credentials, tokens, keys, deploy hooks, or recovery methods remain on client systems unless separately agreed in writing.
- [ ] Mark SRCcvde admin access removed.
- [ ] Begin the retention-only period.

## Days 31–60 — retention-only window

- [ ] Do not perform ongoing maintenance unless separately contracted.
- [ ] Keep relevant Client Project Data only for the agreed retention window.
- [ ] Make the deletion deadline visible to the client.
- [ ] Allow the client to retrieve its documents and available handoff archive during the window.

## Day 60 — final closeout

- [ ] Confirm the 30-day post-aftercare retention period has ended.
- [ ] Disable the client's SRCcvde workspace access.
- [ ] Delete Client Project Data from active SRCcvde systems.
- [ ] Remove handoff ZIP archives and other temporary project copies under SRCcvde's direct control.
- [ ] Retain only permitted Business Records such as executed contracts, amendments, invoices/payment/tax records, and records needed for legal, accounting, insurance, or dispute purposes.
- [ ] Record the deletion/closeout date.
- [ ] Mark the handoff lifecycle complete.

> Contract language and retention practices should be reviewed by qualified counsel for the jurisdictions and records that apply to SRCcvde. This checklist is an operational control, not legal advice.
